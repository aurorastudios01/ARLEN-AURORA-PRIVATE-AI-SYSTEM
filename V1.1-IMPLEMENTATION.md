## Approved Aurora AI interface

The approved Theme 9 / Aurora AI demo is the visual source of truth:

- dark glass panels with purple, blue and cyan aurora lighting;
- small ARLEN logo and top command field;
- left Quick Tools rail;
- system overview immediately left of the animated core;
- animated core in the center, with particles splashing outward from its centre instead of rotating the whole image;
- Command Center below the core;
- AI status, tasks/network and truthful diagnostics on the right;
- compact battery, sound and brightness controls;
- separate calculator, converter, notes, system information and file workspaces.

The supplied luminous particle network is the default core asset. The supplied ARLEN NEXUS logo is used for application branding and the opening screen.

## Responsive screen policy

Qt uses device-independent pixels, so Windows display scaling is handled separately from physical resolution.

| Available application width | Layout |
|---|---|
| 1450 px or more | Full navigation, three-column Aurora dashboard |
| 1100–1449 px | Narrow navigation, compact three-column dashboard |
| 900–1099 px | Icon navigation and single-column scrolling dashboard |
| Below 900 px | Not supported; the application enforces a 900×680 minimum |

Required visual checks before release:

- 1366×768 at 100% and 125% Windows scaling;
- 1600×900 at 100% and 125%;
- 1920×1080 at 100%, 125% and 150%;
- maximized, restored and minimum-size windows;
- long Bangla/English labels, empty data and error messages;
- no overlap, clipped right rail, hidden buttons or horizontal scroll on primary workspaces.

## V0.1–V0.7 problems addressed in V1.1 development

| Previous problem | V1.1 change |
|---|---|
| GGUF folder presence was treated as a ready AI brain | Real Ollama `/api/tags` health and model discovery |
| Separate Home and Chat message models caused duplicate/ghost replies | One SQLite-backed conversation and one QML model |
| Chat required `llama-cpp` and a manually copied GGUF | Local Ollama adapter for `qwen2.5:3b` |
| Vision/OCR readiness was inferred from folders | Real `qwen2.5vl:3b` model detection and selected-image payload |
| Custom sphere overwrote the same filename and could remain cached | Unique visual filenames with remove and reset actions |
| Custom sphere had no removal option | Remove Custom Core and Reset Aurora controls |
| Entire sphere image rotated continuously | Core pulse, orbital rings and centre-out particle splash |
| Right status rail clipped on common laptop resolutions | Responsive width allocation and single-column fallback |
| `sessionUsage` was used as a property instead of a callable Qt slot | Correct slot invocation |
| Voice UI implied a feature that was not shipped | Voice removed from V1.1 navigation and reported as outside scope |
| Updater displayed an obsolete hard-coded version | Development version comes from one application constant |
| Chat history was volatile | Bounded WAL-mode SQLite history |
| File page was mostly decorative | Real bounded filename search, Open and Reveal |
| Local files could not be discovered or organized | Metadata-only local index plus preview/PIN/undo organization for files directly inside Downloads |
| Calculator/converter/notepad were only concepts | Local functional workspace foundations |

## Advantages

- Offline-first text and vision through a local Ollama service.
- 4 GB Lite profile limits context, output tokens, particles and model keep-alive time.
- 8 GB+ profile uses a larger context and smoother animation.
- User data stays in `%LOCALAPPDATA%\ARLEN NEXUS\UserData` across upgrades.
- Image edits are non-destructive and selected local images are not automatically blocked.
- Environment status is truthful: missing services and models remain visibly missing.
- Safe commands are separated from conversational claims.

## Current limitations and open work

- V1.1 is not yet a verified Windows installer or GitHub Release.
- Ollama and both Qwen models remain separate installations during development; the final installer/setup flow must make this easy for non-coders.
- The first implementation of PDF Studio does not yet expose every planned operation in the UI.
- Image prompt editing currently maps understood edit terms to deterministic local filters; it is not a generative image model.
- GPU temperature is not shown unless a reliable hardware telemetry provider is implemented; the UI must not invent a value.
- General delete/rename automation remains disabled. V1.1 only moves previewed files directly inside Downloads into `ARLEN Organized` categories after owner PIN, and records one-level undo.
- Voice, Whisper and TTS are not part of V1.
- Windows rendered screenshots and QML lint must pass before this branch is merged.
